## 结论与证据边界

当前问题同时涉及评测标注覆盖、检索策略和追问改写质量，不能直接归因为“代码写错”或“模型不行”。已确认可改进的实现点；尚无模型对照实验能证明 BGE-M3 是主要瓶颈。

固定基线为 `evaluation/outputs/20261015T081017Z-all/report.json`：30 题正常完成；22 道可回答题中指定证据位置命中 12 道，Recall@5=54.5%；3 道可回答题误拒答；8 道无答案题全部拒答。留出部分为 5/7=71.4%。引用 20/20 可访问只证明引用存在且可读，不证明回答中的每个事实被引用支持。人工正确率、事实支持率仍未复核。

以下逐题分类来自最初的离线诊断，当时仅读取既有报告和源码；后续真实实验与实现结果单列在交付记录。分类是 Agent 诊断，不代替人工验收。

## 已确认的实现特征与待验证假设

- `backend/app/modules/retrieval/service.py` 当前只做 Dense 检索；Top-K=5 时取最多 15 个向量候选，经 MySQL 权限和有效版本复核后按原顺序取前五条，没有语义重排。候选增加不等于结果排名改善，需先看正确证据排在何处。
- `backend/app/modules/indexing/parser.py` 按默认 800 字符递归切分，目标重叠 120；未按 Markdown 章节、表格语义进行完整分段。`indexing/service.py` 只向 Embedding 发送块正文，独立的 `section_title` 未作为检索输入。结构和主题信息不足是待验证原因，不是已证实的根因。
- f03 表明改写可以语法合规却缺少主题。当前 JSON 和问号校验只保证格式，不保证语义完整；需要主题保留的行为验证。
- 本轮 22 道可回答题都保留了 5 条最终候选，未见因生成上下文预算而减少候选条数的现象。当前证据不支持把这批失败归咎于上下文截断。
- `BAAI/bge-m3` 负责向量检索；`Qwen/Qwen3-8B` 负责改写和回答。更换回答模型不会直接改变单轮 Dense 排名。Embedding 是否不足，需要在相同语料、权限范围和题集上对照测试。
- 已有“所有单轮也先改写”的开发集实验仅命中 8/15，并增加延迟，未达到门槛，已撤回；不能把全面增加改写当作已验证的改进。

## 改进顺序与实验设计

### P0：修正评测覆盖，保留旧基线

1. 逐题人工核对参考事实、是否可回答及所有合法等价证据。多事实问题拆为明确的证据单元；每个单元允许多个等价位置，严格限定在同一获授权语料内，不用“答案听起来正确”替代证据。
2. 新题集、证据标注和评分规则独立版本化，先冻结再跑实验；保留 v1 原题、54.5% 报告及失败样本。两个版本的分数分别报告，不能将改标后的差额宣称为代码收益。
3. 修正 MD/Markdown、时间单位等诊断代理的等价处理；代理仍不能代替人工正确率或事实支持率。
4. 原留出题已随全量报告被查看，后续改进也已参考其中案例，不能继续声称它是全新的盲测集。应补充未参与调参的新人工复核留出集，冻结后仅在候选方案确定时验收。

交付：版本化标注、reviewer/理由、评分契约、可复现的 v1/v2 基线。评测器需覆盖等价位置、多证据、部分命中、错误文档/越权位置和切分边界等有效测试。

### P1：先定位“没找到”还是“排不进前五”

在专用测试项目重建固定语料，复核预期证据确实完成解析、生成块并进入当前有效索引。保存开发题的原问题、改写问题、权限内候选排名和实际模型/profile/索引版本。

诊断比较相同查询的 Top-5、Top-10、Top-20 证据覆盖，最终验收仍固定 Recall@5。若证据已在 6–20 名，重点研究排序；若前 20 名也没有，优先检查查询主题、切分和向量表示。必要时用 Qdrant 精确检索诊断近似搜索影响，不能预先假定是数据库缺陷。

候选获取和评分都必须携带当前知识库、有效版本与元数据过滤；不得为了提分删除权限过滤。诊断材料只使用公开测试语料，不把用户正文写入服务日志。

### P2：只在开发集做可解释的单因素改进

| 实验 | 改动与要回答的问题 | 接受条件 |
| --- | --- | --- |
| 追问主题保留 | 改写明确保留历史主题及当前意图；用不同主题、代词、改写失败和注入输入验证。f03 的完整问题应包含文档切分，不硬编码题号或答案。 | 开发集追问召回改善，原问题含义不变；失败降级可见，历史过期来源不混入新证据。 |
| 结构化切分 | 比较章节/段落边界，避免表格表头与关键行失联；用少量预先定义的大小/重叠配置做对照。 | 同一评分版本下 Recall@5 和事实支持改善，位置可追溯，索引体积与耗时可接受。 |
| 标题参与向量表示 | 在不改变原文引用的前提下，比较“标题路径 + 块正文”和现有正文输入。 | 使用新的索引配置/表示版本，文档与查询模型空间保持一致；原文定位仍准确，新版本完整后才发布。 |
| Embedding 对照，按需进行 | 仅当上述诊断仍显示向量表示不足时，核对真实可用供应商/模型及费用，再进行同条件对照。 | 不自动切换收费模型；完整重建隔离的模型空间，记录实际结果，不能凭模型大小或榜单宣布胜出。 |

每次只改变一个因素，保留开发集全部样本和耗时；候选方案确定后再跑冻结的新留出集。失败方案同样留档。不以提高最终 Top-K、增加精选示例或放宽拒答来替代质量提升。

涉及代码变更时，补充有意义的 pytest；模型输入/索引配置变化同步架构、配置快照与版本兼容规则，使用真实 MySQL/Qdrant 验证发布、回退、权限和删除边界。外部模型调用仍在数据库长事务之外。

### P3：Multi-query 与 Rerank 的独立对照，按阶段 6 推进

若证据经常位于候选中但不在前五，阶段 6 的真实 Hybrid/Rerank 值得对照。它们不是当前已完成的改进，不能保证必然达标；按开发计划另行推进，并比较 Dense、Hybrid、Hybrid+Rerank 的同题结果、延迟和实际调用开销。

补充核对（2026-10-15）：原方案 P2 已包含追问 Query Rewrite，P3 已列 Rerank，但遗漏 Multi-query 的显式实验；现补充如下，仍未实现或启用。

| 能力 | 解决的问题 | 本项目优先级 |
| --- | --- | --- |
| Query Rewrite | 将省略主题、含代词的追问补成一个独立检索问题。 | 优先修复现有语义完整性；单轮是否改写单独验证，不强制全部改写。 |
| Multi-query | 为同一意图生成少量不同表达，分别召回，扩大候选覆盖；多事实问题的子问题拆解单独记录，不能混称同义改写。 | 纳入实验，重点观察真实未召回与部分事实缺失的开发题；不预设默认开启。 |
| Rerank | 用原始完整信息需求与候选正文重新评估相关性，从较大的候选池选最终五条。 | 若正确证据已进入候选池却排名靠后，优先对照；可直接接 Dense，不依赖先实现 Hybrid 或 Multi-query。 |

推荐实验链路：追问补全主题 → 保留基准检索问题并生成至多两个额外表达 → 各分支受限召回 → 按 chunk ID 去重并用 RRF 融合 → MySQL 复核当前权限/版本 → 真实 Rerank → 最终 Top-5 → 回答。RRF 融合不等同于模型语义 Rerank；后者不能找回候选池中不存在的证据。该链路是待比较方案，不代表全部组件都应上线。

例如 f03 应先补全为“文档递归切分的默认块长度和目标重叠分别是多少？”，Multi-query 可再生成“文档分块 chunk_size 与 chunk_overlap 的默认配置是什么？”。生成查询只能转换问法，不得猜测或注入 800/120 等答案参数。多事实问题应保留所有子意图；不能只让一个容易回答的子问题挤占全部候选。

首轮实验预算建议每个查询最多取 20 条，最多 3 个查询，融合后至多 40 个候选进入 Rerank，最终仍为 5 条。预算须在实验前冻结，记录实际候选数、调用数、usage 和 p95 耗时；同时比较较大候选池的单查询 Dense+Rerank，区分多查询表达的收益与单纯扩大计算量的收益。预算数值是实验起点，尚未验证可用性能。

对照组至少包括同一修正版 Rewrite 下的单查询 Dense、Multi-query Dense、单查询 Dense+Rerank、Multi-query Dense+Rerank；原实现基线另保留。Hybrid 作为独立因素后续比较，不与其他变更同时加入而无法归因。记录候选池证据覆盖、最终 Recall@5、MRR/nDCG、人工事实支持及延迟，只有稳定收益才考虑默认启用。

所有查询分支都强制相同的服务端权限/有效版本/元数据范围，融合不能引入未授权候选；候选正文发送外部 Rerank 前和最终输出前继续复核。增加查询数要有总 deadline、并发上限及去重；查询生成或 Rerank 故障的失败/降级必须显式记录，只能返回仍通过权限和版本检查的真实 Dense 结果，不能用假排序或无过滤查询掩盖故障。真实 Rerank 供应商、模型和费用尚未选择。

技术依据（2026-10-15 核对）：[Query Rewriting 原论文](https://aclanthology.org/2023.emnlp-main.322/)、[多查询改写研究](https://arxiv.org/abs/2407.10670)、[Qdrant 候选召回与 Rerank](https://qdrant.tech/documentation/tutorials-basics/reranking-hybrid-search/)。这些资料支持实验方向，不证明本项目必然获益。

## 验收与停止条件

维持阶段 5 的既定门槛：证据 Recall@5 ≥0.80；人工正确率、事实支持率均 ≥0.80；引用有效率 1.00；原 8 道无答案题至少 7 道正确拒答。多证据口径和新留出集的统计方式须在执行前冻结，并单列可回答题误拒答。当前 22 道单证据题的 80% 至少需要 18 道命中；不能以四舍五入绕过门槛。

所有方案必须保持越权/已删除来源泄漏为零、真实服务回归通过；记录检索/首 token/总耗时及 usage，保持现有 30 秒读取和 120 秒总 deadline。新增语料或配置更改后保存语料、题集、代码、Prompt、锁文件和模型/profile 哈希与版本；供应商权重仍只能如实记录 provider-managed。

若没有足够真实收益，保留当前实现和未达标状态，依据实验结果决定下一项改进。方案本身不代表质量验收完成。
