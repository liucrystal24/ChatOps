- [x] 创建最小 Vue + TypeScript + Vite + Element Plus 页面，显示 API/依赖真实健康状态。

- [x] 建立 pytest 单元/服务集成标记、前端类型检查与构建脚本，更新实际运行说明。

验收必须逐条满足：

1. Docker daemon 可用；从干净配置能 build/start，基础容器处于预期健康状态，迁移成功退出，API/前端可访问。
2. `/health/live` 返回 200；ready 正确显示 MySQL/Qdrant 连通与迁移状态；停止依赖后 ready 返回 503，live 仍可用。检查结束恢复服务。
3. 从锁文件安装成功，pytest 冒烟及配置/错误处理测试通过，前端类型检查和 production build 通过。
4. 日志与错误响应没有凭据，`.env.example` 无密钥，前端构建产物不含后端密钥。
5. 重启数据服务后能验证命名卷持久化；采用专门测试资源，不破坏用户数据。
6. README 给出实际验证的安装、启动、迁移、测试及停止命令，并说明缺模型配置时的能力状态。

本阶段不接文档解析、模型或问答，不需要用户提供模型密钥。第一阶段记录的 Docker 无法连接问题已通过启动 Docker Desktop 解决。

验收结果：以上 6 条均已实际验证。Docker daemon 已启动；19 项后端单元/真实服务测试、3 项前端行为测试、类型检查/构建、依赖停启、命名卷持久化、密钥扫描和 OpenAPI 比对均通过。实际命令、镜像 digest、已修复兼容问题和未验证边界见 [stage-2-delivery.md](stage-2-delivery.md)。阶段 3 结果见下一节。

## 阶段 3：身份与知识库隔离（已完成，2026-10-15）

- [x] users、knowledge_bases、members 迁移；管理 CLI 创建/停用真实用户。
- [x] Argon2 登录、短期 JWT、用户有效状态检查、基本登录限流。
- [x] 知识库创建/列表/详情/修改、空库删除、成员角色管理；profile 未接模型时可暂不绑定。
- [x] 前端登录及知识库/成员管理页面连接真实接口。
- [x] 覆盖成员隔离、角色边界、最后 owner、并发 owner 修改与用户停用规则。

验收：至少两个真实测试账号，A 的私有库不能被 B 列表/详情获取；viewer 可读不能写；editor 不能管成员；owner 规则在真实 MySQL 并发事务下成立。JWT 仍有效但用户停用或成员被移除时访问立即按当前数据库状态拒绝。无模型凭据也能完成这一阶段。

验收结果：48 项后端测试（29 unit + 19 真实服务 integration）、6 项前端行为测试、类型检查/构建通过；真实 CLI/Web HTTP 与浏览器双账号验证通过。新增 authorization_guard 单行锁协调跨库用户停用与成员变更，四种 owner 并发变更及锁等待/锁后重新鉴权均已验证。默认 8080 实例已升级，未创建默认账号，RAG 能力仍为 false。完整检查、限制及下一阶段条件见 [stage-3-delivery.md](stage-3-delivery.md)。阶段 4 的当前进度见下一节。

## 阶段 4：文档索引与真实 Dense 检索（实现完成，最终验收中）

按以下小增量交付，每个增量有实际执行结果：

1. 文件上传与逻辑删除、大小/格式/配额限制、文档和任务迁移。
2. Worker 领取、租约、巡检、状态和重试；先验证状态机，不伪造 Embedding 完成。
3. TXT/MD/文字 PDF 解析、中文 Chunking 和来源定位；真实文件测试。
4. 接入选定真实 Embedding，探测 profile/维度，写 Qdrant 并原子发布有效版本。
5. Dense Top-K、文档/类型/标签过滤及授权范围复核；先通过服务集成入口验收，不为演示新增绕过鉴权的临时 HTTP 路由。
6. 前端上传、任务状态、失败详情/重试、重建、删除和来源读取。

验收：真实上传文件出现有效 Chunk/向量并能按问题检索；PDF 引用页码可核验；扫描 PDF 明确失败。模拟“外部服务故障”的测试只能用故障注入，不能以假向量替代 live 验收。Worker 被终止后任务可恢复；旧 Worker 不可发布；局部写入不进入检索；重复 upsert 不增长重复点；重建失败保留旧版本；逻辑删除后旧向量残留也不会召回。B 对 A 库的检索、Chunk、文件和任务读取都被拒绝。

阶段入口前确认真实供应商、Embedding 模型、token/批量/维度限制及凭据环境变量。不要求把密钥粘贴到聊天或写入仓库。

## 阶段 6：检索优化与对比实验

- [ ] 引入真实 sparse 编码与中文分词，扩展 collection 并补索引；所有 prefetch 强制同一授权范围。
- [ ] Dense/sparse RRF Hybrid，对齐 Top-K、候选数量、过滤和评分解释。
- [ ] 真实 Rerank，候选量上限、timeout、可见降级与引用映射。
- [ ] 同一题集比较 Dense、Hybrid、Hybrid + Rerank；记录 Recall、MRR/nDCG、引用、拒答、耗时和调用开销。
- [ ] 只在验证质量收益和可接受延迟后调整默认策略；不以几个精选问题代替整体对比。

验收：无权限/已删除文档在每个召回分支和 Rerank 输入中均为零；真实优化实验可复现，失败/降级单独报告；未达质量或延迟目标则保留 Dense 默认并如实记录结果，不能硬宣称优化有效。
