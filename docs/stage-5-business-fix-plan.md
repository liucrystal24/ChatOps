# 阶段5业务集错误修复设计

2026-10-16。实施依据：business-v1首轮a13/a14/a18/u05；保留文章、题集、评分、首轮报告及Agent审核。以下为实施设计，实际验证另记，不预先标记完成。

1. 使用共享的轻量Markdown表格解析，识别表头、分隔行、行和原文区间，支持普通表格及权限表。每条行证据保留表头/分隔行/本行；无表头、列数不一致、围栏代码等不推断。不可将表头转换出的文字伪作原文。
2. extractive-v2在候选原文上约束问题中显式出现的套餐/版本、角色、文件类型和部分可识别属性。正文显式对象冲突时优先排除；章节只补充上下文，不代替原文证明具体数值。签署地点须有地点关系，日期不能顶替；额外条件问题须有该操作及前提。缺可验证依据固定拒答，同时验证正常回答。规则只读问题和当前获授权来源，禁止读取题号、品牌固定值或评测标签。
3. 对比table-fields-v1索引表示：保持Chunk原文/字符位置、点数、模型profile和Dense权限过滤；仅给完整表格的向量输入附加字段-值关联及章节。配置和表示写入版本快照，原文输出不变。默认是否启用由真实服务回归决定；旧版本不重写，用户明确重建后才采用新表示。不开启Multi-query、Hybrid或Rerank。
4. 所有来源继续先由MySQL有效版本及成员权限复核。中间JSON不输出；规则/格式不通过不发送事实delta；每秒监视、取消、幂等和落库后done保留。
