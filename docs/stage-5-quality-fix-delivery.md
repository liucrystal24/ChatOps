## 问题、原因、解决方案

| 问题 | 原因 | 解决方案 |
| --- | --- | --- |
| u05 把交付记录日期当成合同签署日期 | 检索到了有日期的相关文档，但没有合同签署事实。模型自由生成时错绑事件；旧校验只验证S1存在。 | 签约日期证据须同时明确签约事件与日期，排除未签署/无记载及仅更新日期；无可用依据直接拒答。服务端只输出获准的原文字面摘录，不让模型生成另一个日期。新增无日期、真实签约日期、两种日期并存和标题日期等正反例。 |
| f04 把 owner 专属成员列表接口说成 viewer 权限 | 同一个表格包含多种角色，模型跨行套用条件，旧引用校验看不到操作与角色关系。 | 简单权限表按“表头+本行”建立证据；按项目owner/editor/viewer及+层级筛选，不把owner行用于viewer权限回答。缺失表头/无法可靠解析时不猜。保留真实后端鉴权，摘录规则不授予任何权限。补列序、行序、转义竖线及拒绝对照。 |
| s15 用200个文档代替500 MiB累计容量 | 数量和容量同时在Top-5；自由改写混用指标，漏答已有的容量依据。 | 容量问题排除只有个数的证据；原文保留对象和MB/MiB单位，同时问每库和文件卷时要求两个范围均有证据。新增容量、数量、单文件、无容量依据及歧义问法对照，不修改原题。 |
| s02 将应用概括成一种存储 | 模型重新分类、概括，偏离原文“本地部署组件”的表达。 | 返回原文“本地部署应用、MySQL、Qdrant和文件存储，模型通过供应商API调用”，不额外生成分类结论。 |
| 首轮摘录回归漏掉“永久错误不重试”等后半句条件 | 机械按分号切开关联语句，使模型只选了前半句，遗漏限定条件。 | “仅、按、但、且、并”等承接分句与前句绑定；独立主语的任务超时与Worker租约仍分开。租约时长问题只接受租约/续租的时间证据。增加规则测试，完整题集复测s07/s08/s16。 |
| 未验证文本先发到浏览器，最后仅核对引用编号 | 引用编号有效无法保证事实支持；即使最终失败，错误草稿也已展示。 | 模型使用现有JSON mode只选证据编号；先验证结构、编号、去重、原文区间及上述类型规则，再发送摘录delta。非法结构返回ANSWER_PLAN_INVALID，不补造引用、不冒充拒答成功。中间JSON不写正文、不输出。每秒权限/有效版本检查、取消、落库后done保持执行。 |

证据目录和规则在 `backend/app/modules/chat/evidence.py`，提示在 `chat/prompt.py`，编排在 `chat/service.py`。规则没有读取评测题号、预期答案或黄金证据；只处理本轮获授权来源和问题。所有原40题、语料及评分规则保留，历史失败报告未覆盖。

## 取舍与仍需验收的内容

回答改为证据摘录，表达不如自由生成自然；选择器仍可能选入多余句子，不能把字面原文一致当成任意问题的语义完整证明。复杂表格、跨句隐含关系、日期省略事件和未覆盖的单位写法可能被保守拒答，普通非权限表目前不进入摘录目录。这些边界未经过大规模私有业务语料评估，不能宣称通用事实正确率100%。

本轮针对已知三类错误完成工程修复和公开题集回归；人工标注、逐答案正确率/事实支持率仍按原决定待审核。阶段5整体验收因此保持进行中；这项待办不代表把工程修复推迟到阶段6。Multi-query、Hybrid、Rerank和更换模型均未在本轮实施。

阶段5剩余验收标准：真人复核参考标注、答案正确率与事实支持率均达到0.80；引用有效率1.00、权限泄漏为零、原8道无答案题至少7道正确拒答。后面三项已得到本轮自动检查支持，不能替代前两项人工判断；发现新反例仍在本阶段定位修复。
