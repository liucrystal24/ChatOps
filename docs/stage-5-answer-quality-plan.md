# 阶段 5 已知生成错误的修复方案

日期：2026-10-15。状态：原因复核与修复设计已完成，以下新增改动尚未实现或验证。属于阶段5，不转交阶段6；用户暂留人工复核的决定不阻止已知错误的工程修复。

## 已确认的现象与原因边界

依据：`evaluation/outputs/20261015T121205Z-all/report.json` 的实际问题、候选及引用，并核对当前 `chat/prompt.py`、`chat/service.py`。

| 样本 | 实际证据与错误 | 已确认的问题 |
| --- | --- | --- |
| u05 合同签署日期 | 被引S1是阶段4交付记录的日期，没有合同签署信息，模型仍回答该日期。 | 把一个日期值绑定到了原文没有描述的事件；正确行为是拒答。不能靠把这个无答案问题改成可回答解决。 |
| f04 viewer权限 | S1明说viewer只读及问答；S2表格中GET members为owner，生成却扩展成viewer可读成员列表。 | 跨表格行套用角色条件，并额外生成并非必要的操作清单。后端实际成员接口仍要求owner，回答错误不等于授权规则被绕过。 |
| s15 配额 | S2有500 MiB/2 GiB；模型用了S1的200个文档作第一个限制。 | 正确证据虽命中，模型仍混用数量与容量。原题“文件累计”没有明确写容量，也有题意歧义；保留旧题及评分，新增明确容量、明确数量与含混问法的对照，不通过改题凑分。 |

当前 `validate_answer` 只检查固定拒答，或答案引用编号属于本轮候选。编号合法并不验证对象、事件、角色、操作、数值、单位及否定条件是否对应。因此当前系统会把这些错误保存成completed。这是答案校验的工程缺口，不仅是提示不够详细。

现有Top-5上下文也会同时包含多种配额或整个权限表，增加混淆机会。已实测当前Qwen3-8B在这种输入下出错；尚未做同条件模型对照，不能据此断言只能换模型或某个模型一定解决。

## 已试过但没有解决的办法

- 加强事件/日期、数值/单位、表格逐行与引用提示，并把标题传入生成；仍有上述反例。
- 保留标题和首段，避免日期成为孤立块；仍未使合同日期题稳定拒答。
- 同一模型生成前只返回answerable布尔值：仍放过合同日期，另误拒答权限题；已撤回，不能把多调用一次称为可靠校验。

下一轮不把“再加一句提示”或“同模型自评通过”当作完整解决方案。

## 修复顺序

### 1. 先固化语义回归与反例

保留全部原40题、报告及评分；把u05/f04/s15登记为已知生成缺陷。冻结新的开发对照集，至少覆盖：

- 仅有文件更新日期；确有合同签署日期；两者同时存在且日期不同。
- viewer可读与owner专属的相邻表格行，改变行序、列序和问法；普通viewer仍被真实API拒绝成员列表。
- 同时有数量上限、容量上限、单文件上限与文件卷上限；提问分别指定数量/容量，另保留歧义问法。MB与MiB不能无依据互换。
- 正确与错误的来源编号、数值碰巧相同但属性不同、否定权限、有明确答案的对照，防止一律拒答获得表面高分。

pytest应分别覆盖可确定的结构/位置/单位规则、真实MySQL权限及版本规则；真实模型回归检验最终行为。有限样本的自动语义断言不冒充人工正确率。

### 2. 调整生成上下文的证据表示

在现有服务层准备模型上下文时，将表格表头与对应行一起表达，保留角色、操作和原文位置；日期保留所属文档/章节和事件上下文；配额显式保留对象、指标及单位。保持原文、页码及字符范围可追溯，派生描述不能替换原文成为伪证据。

首先固定检索结果与模型，只比较上下文表示，隔离改动收益。不改变权限范围或Top-K，也不引入排序模型。复杂/无法可靠解析的表格不伪装成已识别的结构化事实，继续按原文保守处理。

### 3. 从“编号校验”推进到“逐主张证据绑定”

设计并验证中间结构：每项主张携带对象/关系、值与单位、来源编号、原文证据区间；缺少依据的要求单独声明。生成最终文本前由服务校验结构、授权版本、原文区间、实际引文及可确定的数值/单位一致性。

引用原文中出现过同一个数字还不够，必须检查其所限定的属性。不得把合同事件与交付元数据混用，也不得把相邻owner行当作viewer行。字面校验不能证明任意自然语言蕴含；无法判定的关系保守拒答或标为失败，不能宣称通用事实正确性已被代码完全证明。

中间结构不得由模型伪造通过后自动补引用。若需要改变SSE输出时机或协议，先更新接口契约、OpenAPI和前端行为测试；未经验证的事实不先作为最终答案发出。完整预算、超时、取消、每秒权限检查、落库后done、原有版本隔离继续成立。

### 4. 必要时做生成模型对照

若固定上下文与证据绑定后仍不达标，用相同证据输入比较生成模型，分别记录语义正确、拒答、引用支持、延迟及实际usage。供应商、模型可用性和价格需先核对；不自动切换收费模型。

更换生成模型是解决阶段5质量问题的可选手段，不必等阶段6，也不保证一定获益。更换Embedding对这三个“证据已找到/应当拒答”的错误没有直接针对性。

## 验收与阶段边界

- 已知三类反例及其新对照集通过，不能只硬编码原题答案、题号、日期或数字。
- 全部冻结题集回归，保持Recall@5≥0.80、引用有效率1.00、原8道无答案拒答至少7道；同时单列错误答案、误拒答、失败与调用开销。
- 不引入权限泄漏，真实服务回归通过；人工正确率/事实支持率≥0.80仍须真人审核，按用户要求暂留待办。
- 若实测无收益或引入更多误拒答，不默认上线；保存失败结果并继续定位，不能以“需要人工审核”为由把已知工程缺陷标成已解决。

阶段6的Multi-query/Hybrid/Rerank主要研究候选覆盖与排名，可作为后续独立实验；不会自动修正已经召回后的事件绑定、权限主张或单位混淆。上述生成与校验修复属于阶段5质量收尾。
